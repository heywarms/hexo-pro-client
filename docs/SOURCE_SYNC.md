# 博客源码上传与云同步

## 日常在手机和电脑之间同步

打开侧栏「系统管理 → 云同步」，填写与手机相同的 GitHub 源码仓库、分支和访问凭据。点击「检查变更」会保存连接设置，并列出待上传、待下载和需要选择版本的文件。点击文件名可查看两边内容；选择冲突文件的保留版本后，点击「同步这些变更」。首次同步会保留两边各自新增的文件，不会根据本机缺少文件就删除远程文件。

云同步在 `.hexo-pro/cloud-sync/` 中维护独立工作区和上次同步记录，不修改博客原有的 Git 分支、暂存区、提交历史或远程地址。相同文件两边都修改时停止自动覆盖；不同文章的 ID 记录可以自动合并。预览后文件或远程提交发生变化时，必须重新检查；推送不会使用强制覆盖。下载覆盖或删除本机文件前，原文件会备份到 `.hexo-pro/cloud-sync/<仓库标识>/backups/`。同步中断的恢复记录也保存在这里，备份和同步缓存不会上传。

文章及 Front Matter 按原始字节同步。Hexo 配置中的 `deploy` 设置保留本机值，不作为云同步差异；其他 Hexo 配置按 YAML 内容比较。依赖、生成产物、Git 内部数据和本机凭据被排除；项目中的 `.gitignore` 规则继续生效。GitHub 凭据只保存在本机权限受限的 `sync_config.json` 中，不进入同步工作区的 Git 配置或日志。令牌需要目标仓库 Contents 读写权限；同步 `.github/workflows/` 时还需要 Workflows 写入权限。

「部署网站」用于发布站点；其历史“跳过生成”模式仍可用于将源码交给 GitHub Actions 构建，但属于单向部署。请勿把源码云同步与生成站点的部署设为同一分支。

## 部署页的源码模式

部署页开启“跳过生成”后，会把博客项目的源文件复制到独立的部署工作区，再提交到配置的仓库和分支。文件范围包括文章、图片、主题、所有主题配置、脚本、工作流、依赖声明和锁文件，以及 `.hexo-pro/document-identities.json`。

复制使用 Git 解析项目内各级 `.gitignore`，保留其否定规则与转义语义。文章 ID 索引和根 `.gitignore` 会始终保留；上传副本中的忽略规则会明确允许身份索引。Markdown、Front Matter 和 ID 索引按原字节复制。

以下本机数据不属于源码上传内容：依赖目录、Git 内部目录、配置的静态输出目录、部署缓存、`.env` 文件、日志、Hexo 数据库、Hexo Pro 用户及运行数据库、部署和同步凭据配置，以及身份索引的备份与锁文件。`.github`、`.gitignore` 和 `.gitattributes` 不会因为名称包含 `.git` 被误过滤。

`_config.yml` 的部署配置会在副本中去掉 URL 用户信息和令牌字段。无法解析配置时停止上传，不回退到包含凭据的原始副本。本地配置与文章不被改写。

源码部署上传的是当前电脑的一份快照，不会自动合并手机的修改。手机和电脑轮流写作时，应使用独立的「云同步」页面，避免用旧的电脑快照覆盖其他设备的新内容。静态站点部署应使用单独的分支或仓库。

回归测试：`node --test test/cloud-sync.test.js test/source-deploy-api.test.js test/source-sync.test.js test/sync-service.test.js test/document-identity.test.js`。通过临时本地 Git 远程仓库验证首次同步、双向变更、ID 合并、冲突选择、备份、并发更新拒绝、完整部署流程和凭据保留；测试不连接或写入真实 GitHub 仓库。
