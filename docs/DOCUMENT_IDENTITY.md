# 文章的永久标识

Hexo 的 `_id` 属于生成缓存，清理缓存后可能重新分配。文章的 `source`、`permalink`、域名和端口也可能变化，因此不适合直接作为编辑器的永久标识。

Hexo Pro 为文章和页面分配 UUID，在博客目录的 `.hexo-pro/document-identities.json` 中记录 UUID、文件位置和内容指纹。初始化身份索引只写这个独立文件，不修改 Markdown 文件、Front Matter、公开网址或插件字段。API 返回的 `documentId` 和 Hexo 的 `_id`、`id` 分开使用。

从列表、搜索、仪表盘或创建入口打开的编辑器使用 UUID。旧的 Base64 网址链接仍可打开当前地址对应的文章，并自动替换为 UUID 编辑链接；域名或端口变化时，可以按未变的 URL 路径兼容查找。历史路径也改变的旧网址不能保证恢复，应从列表重新打开。

编辑器内的改名、发布、撤回、删除和恢复会同步更新索引。普通内容编辑、重启服务、清理 Hexo 缓存、切换主题和修改链接规则不会重新分配 ID。直接复制 Markdown 文件会得到独立 ID。

在编辑器外移动文件时，只有原文件已消失且内容指纹唯一匹配，才沿用旧 ID。如果在外部同时改名并修改内容，或者有多份相同内容无法判定，会分配新 ID，原 UUID 不会指向猜测的文件。此时从列表重新打开即可。

身份索引属于博客源数据，迁移电脑、备份或同步博客时应一起保留。“GitHub 云同步”和部署页开启“跳过生成”后的源码上传都会将这个 JSON 文件纳入版本管理，即使原有 `.gitignore` 排除了 `.hexo-pro/`。同目录的运行信息、锁文件和备份不会上传。关闭“跳过生成”时部署的是生成后的静态站点，不包含身份索引。不要将身份索引与 Hexo 的 `db.json` 一起清理。写入采用临时文件和原子替换，并保留上一版 `.bak`；索引损坏或丢失时会明确报错，避免静默生成一批新 ID。

MCP 的获取、更新、发布、撤回支持 `documentId`，仍兼容 `permalink`。优先使用列表或搜索返回的 `documentId`。

运行 `yarn test:identity` 验证身份稳定性、原文不变、移动和复制、回收站恢复、插件字段及索引损坏处理。
